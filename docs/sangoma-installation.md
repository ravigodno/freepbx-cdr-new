# Sangoma 7: установка и обновление PBXPuls

## Runtime и границы поддержки

Для Sangoma 7 x86_64/glibc 2.17 используется закреплённая опубликованная
`node-v22.23.2-linux-x64-glibc-217` из Node.js unofficial-builds. Это экспериментальная
сборка сообщества, а не официально поддерживаемая Node.js платформа. Устаревшие ОС
и библиотеки не получают поддержку от этого релиза PBXPuls. Полная совместимость
всех AI-провайдеров и функций с MariaDB 5.5 не заявляется.

Установщик проверяет SHA256 по опубликованному SHASUMS256.txt и фактический запуск
Node/npm. Адреса `latest-v22.x` не используются. На новых поддерживаемых Linux с
glibc >=2.28 выбирается официальный архив той же версии.

По умолчанию runtime находится в
`/opt/pbxpuls-runtime/node-v22.23.2-linux-x64-glibc-217`.
`/usr/bin/node`, системные npm, MariaDB, glibc, libstdc++ и FreePBX не обновляются.
Устанавливаются только отсутствующие утилиты git/curl/openssl/nc; отсутствие
mysql/tar/xz/sha256sum/ss выявляется предварительной проверкой.

Файл `.pbxpuls-runtime` (root, 0600) закрепляет PBXPULS_NODE_HOME, PM2_HOME и имя
systemd-службы. Установка, сборка, запуск и обновление используют его. Глобальный
PM2 устанавливается в выделенный runtime. Чистая установка использует собственный
PM2_HOME и службу `pbxpuls-pm2`; существующее приложение с root PM2 сохраняет свой
PM2_HOME и `pm2-root`. Если в этом home есть другие приложения, автоматическое
обновление прекращается: необходим отдельный план переноса.

## Чистая установка и продолжение

Запускать от root из загруженной копии install.sh тега v5.8.27. До изменений
проверяются ОС, архитектура, glibc, занятые порты, FreePBX и доступ к MariaDB.
Можно выполнить только предварительную проверку: `PBXPULS_PREFLIGHT_ONLY=1 bash install.sh`.
Существующая установка без служебного маркера не принимается за чистую.

`.pbxpuls-install-state` хранит сгенерированные секреты с правами 0600 **до**
создания пользователей MariaDB/AMI. Не удалять этот файл при ошибке.
Продолжение прерванной установки:

```bash
PBXPULS_RESUME=1 bash /root/install-v5.8.27.sh
```

Пароли существующих SQL-пользователей не меняются. Если учётная запись уже была
создана вне этой установки с другим паролем, остановиться и согласовать учётные
данные в root-файлах состояния и `.env`; не удалять пользователя и не сбрасывать
пароль ради повторного запуска. Установщик не предназначен для повторного
инициализирования уже эксплуатируемой панели: используйте обновление.

Ошибка любой миграции или незавершённый список ожидаемых миграций даёт ненулевой
код завершения. `--bootstrap-only` создаёт первоначальную конфигурацию штатным
механизмом без запуска приложения. Проверка БД также проверяет пользователей,
роли, назначения ролей и разрешения. DDL в MariaDB не транзакционен: при повторе
уже выполненные ADD COLUMN/INDEX распознаются, журнал ставится только после всей
миграции. Другие ошибки не скрываются.

## Обновление с локальными исправлениями

Выполнять в окно обслуживания без активных AI-звонков. Полная копия MariaDB может
занять значительное время и место: обеспечить место для дампа, старой сборки и
зависимостей. Скрипт не перезапускает FreePBX/Asterisk.

Точная команда для стандартного каталога и указанного runtime:

```bash
curl -fSL https://raw.githubusercontent.com/ravigodno/freepbx-cdr-new/v5.8.27/scripts/update-pbxpuls.sh -o /root/update-pbxpuls-v5.8.27.sh
PBXPULS_NODE_HOME=/opt/pbxpuls-runtime/node-v22.23.2-linux-x64-glibc-217 bash /root/update-pbxpuls-v5.8.27.sh v5.8.27
```

Для другого каталога добавить `PBXPULS_INSTALL_DIR=/полный/путь`.
Скрипт сохраняет diff HEAD и индекс, `.env`, конфигурацию PM2, старую сборку,
MariaDB и legacy data. Локальные изменения интегрируются в отдельной рабочей
копии. Уже включённый патч распознаётся; конфликт останавливает обновление до
остановки приложения. Неразрешённый конфликт надо разобрать по сохранённому diff,
не выполнять `git reset --hard`. Untracked клиентские файлы не публикуются и не
удаляются. Секреты/резервные копии не добавляются в Git.

После сборки останавливается только PBXPuls, заменяются код и зависимости,
выполняются миграции, проверяется справочник, затем PM2/systemd и HTTP. Обновление
согласованного SQL-справочника не импортирует заново устаревший JSON.

## Справочник: проверка и безопасное восстановление

При смешанных режимах запись блокируется с объяснением вместо записи в другое
хранилище. Для импорта необходимы SQL-чтение, SQL-запись и штатная проверка готовности.
Недоступный SQL не подменяется устаревшими JSON-контактами.

Из каталога приложения, с PATH выделенного runtime:

```bash
export PATH=/opt/pbxpuls-runtime/node-v22.23.2-linux-x64-glibc-217/bin:$PATH
node node_modules/tsx/dist/cli.mjs scripts/directory-storage.ts
```

Предпросмотр содержит только числа, типы конфликтов, режимы и digest. Проверяются
ID, телефоны с владельцами, видимость, поля контактов, метаданные и определения
дополнительных полей. Конфликт не решается автоматически в пользу JSON или SQL.
Сначала сохранить БД/legacy-файл и установить, какая запись актуальна. Совпадение
номера с другим ID не является основанием для создания дубликата.

Если `canApply=true`, после остановки PBXPuls и просмотра результата:

```bash
PBXPULS_MAINTENANCE=1 node node_modules/tsx/dist/cli.mjs scripts/directory-storage.ts --apply --expect DIGEST_ИЗ_ПРЕДПРОСМОТРА
```

При изменившемся digest операция отменяется. Отсутствующие неконфликтующие записи
переносятся с прежними ID, владельцами и метаданными в транзакции; количество и
содержимое проверяются перед переключением обоих режимов через штатный guard.
Повторная операция не создаёт копии. JSON остаётся для ручного восстановления,
но после переключения не используется для чтения/записи контактов.

## Откат

Скрипт печатает путь `/root/pbxpuls-update-XXXXXX` и точную команду:

```bash
bash /root/pbxpuls-update-XXXXXX/rollback.sh
```

Она возвращает предыдущий коммит, локальные изменения, зависимости, сборку и
определение процесса PM2. Данные MariaDB автоматически назад не откатываются:
новые записи после обновления не должны быть потеряны. Если требуется восстановить
саму БД, отдельно остановить PBXPuls, сохранить её текущее состояние, проверить
имя БД в `.env`, восстановить **только PBXPuls** из `database.sql`, при необходимости
legacy-файлы из `legacy-data.tar.gz` и `.env` из `env`, затем выполнить проверку БД
и запустить сохранённое определение PM2. Не импортировать дамп в asterisk/asteriskcdrdb.

## Проверка интерфейса

- Обновить страницу без кэша. Импортировать небольшую тестовую CSV, открыть запись,
  изменить и удалить её; проверить внутренний, связанный, дополнительные номера,
  email, отдел и пользовательские поля.
- Под обычным пользователем проверить недоступность чужих личных контактов.
- Кнопка связанного номера доступна Tab и имеет подсказку; для реального тестового
  вызова отдельно выбрать устройство/подтвердить вызов штатным способом.
- В истории звонков проверить сотрудника из фактически ответившего канала,
  неизвестный статус ненаблюдавшихся участников и различие CDR/CEL.
- Проверить systemctl is-enabled/is-active для службы из `.pbxpuls-runtime`, один
  процесс PM2, локальный HTTP и восстановление после согласованной перезагрузки.
