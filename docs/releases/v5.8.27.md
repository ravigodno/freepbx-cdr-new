# PBXPuls v5.8.27

Исправлены выявленные на Sangoma Linux 7 причины сбоев установки, невидимых SQL-контактов и неверного ответившего участника в истории звонка.

- Предварительные проверки до системных изменений; выделенный Node.js 22.23.2, закреплённый архив glibc-217 с SHA256 и проверкой запуска; отдельные npm/PM2/PATH и проверяемая служба systemd. Системные компоненты FreePBX не обновляются.
- MariaDB 5.5: создание пользователя без CREATE USER IF NOT EXISTS и без смены существующего пароля. Секреты сохраняются до операций, прерванная установка продолжается с ними.
- Единая загрузка конфигурации; ошибки миграций прерывают CLI и запуск. Проверяется весь ожидаемый журнал, пользователи/роли/связи. Пустая схема больше не считается отказом подключения и не вызывает переход к другой БД.
- Согласованные режимы импорта и CRUD справочника. Смешанные режимы блокируются с объяснением. Добавлены предпросмотр и проверяемый перенос неконфликтующих JSON-контактов с сохранением ID/владельцев/метаданных. Уже активный SQL не перезаполняется старым JSON.
- В сокращённом списке присутствуют internalExtension и linkedExternalNumber. Связанный номер использует общую доступную с клавиатуры кнопку звонка и штатный обработчик.
- Сервер и таймлайн используют общее доказательство ответа: SIP/PJSIP-канал, корреляция linkedid, соединение CEL с длительностью; CDR-only вывод отмечается отдельно. Номер группы/очереди, ответ объявления и billsec при NO ANSWER не считаются ответом сотрудника. Одинаковые uniqueid не схлопывают строки. Текущий состав группы и postdest не выдаются за исторические события.
- Обновляющий скрипт сохраняет локальные diff и данные, собирает интегрированный релиз отдельно и останавливается при конфликте. Есть сохранённая команда отката; без git reset --hard.

## Проверки

На изолированном экземпляре MariaDB **5.5.65**, InnoDB Antelope,
file_per_table=OFF, large_prefix=OFF: **139 таблиц, все 96 миграций** до
20260908_096_mcn_balance_source, повторный запуск, восстановление после частичного
DDL, отказ при отсутствующей миграции, сохранение пароля существующего пользователя.

Реальный SQL/HTTP-тест импорта и дальнейших list/card/update/read/delete операций,
общие/личные контакты и права, сохранность метаданных; перенос legacy без дублей,
отказ при конфликтах и устаревшем предпросмотре. Обезличенные CDR/CEL-фикстуры группы
7000 → 781, объявления, ненаблюдавшихся участников, NO ANSWER с billsec, очереди,
SIP/PJSIP/Local, последовательных направлений и перевода. UI-handler проверен без звонков.

Изолированный PM2_HOME и отдельная systemd-служба: enabled/active, два перезапуска,
один процесс, отдельный Node.js, HTTP. Отдельный Git-стенд проверил интеграцию уже
включённого патча, сохранение локальной правки, ручной и автоматический откат
(внешние операции обновляющего скрипта в этом тесте подменены). TypeScript,
профильные регрессии и production build.

## Ограничения

Не выполнялись полная перезагрузка хоста, установка на другую чистую реальную АТС,
живые телефонные звонки и браузерный E2E. Бенчмарк на 100 000 контактов не выполнялся;
проверены функциональные SQL-сценарии. Успешные миграции не доказывают совместимость
всех функций с MariaDB 5.5. glibc-217 — экспериментальная сборка сообщества, а не
официальная поддержка Sangoma 7 проектом Node.js. Ограничения AI-пилота v5.8.25 сохраняются.

Новых миграций бизнес-схемы нет. Полная инструкция, точная команда обновления,
разбор конфликтов справочника и порядок отката:
[Установка и обновление на Sangoma 7](https://github.com/ravigodno/freepbx-cdr-new/blob/v5.8.27/docs/sangoma-installation.md).

Релиз автоматически на действующие АТС не устанавливается. Артефакты — стандартные
исходные архивы GitHub; клиентские данные, .env, ключи и дампы в релиз не включены.
