# PBXPuls v5.8.33

Исправлены статусы SLA перезвона в реестре звонков. При лимите 5 минут успешный перезвон через 9 минут показывается красным как обработанный с превышением SLA.

## Изменения

- Реестр использует «SLA перезвона» из настроек (missedCallCallbackSlaMinutes). Старое поле callbackKpiMinutes с исходным значением 60 минут больше не подменяет этот лимит при расчётах реестра, статистики и отчётов.
- Серверный статус SLA имеет приоритет над устаревшими признаками обработки при выборе цвета и подсказки.
- Срок сравнивается без округления задержки вниз: ровно 5 минут укладываются в лимит 5 минут, 5 минут 1 секунда — уже превышение.
- Строка реестра передаёт в компонент статуса серверные признаки обработки и потери звонка.

## Проверки

- test:cdr-sla-status: превышение SLA при старом положительном KPI, смена настройки с 5 на 10 минут, граница срока, ожидание и потерянный звонок.
- test:missed-call-callback-sla и test:reports-analytics-enhancements.
- npm run lint и npm run build.
- Исправление проверено сборкой и тестами на рабочей установке; после перезапуска проверены HTTP-ответ и выдача новой сборки интерфейса. Проверка конкретного клиентского звонка через авторизованный интерфейс не выполнялась.

Новых зависимостей и миграций базы данных нет. SLA ответа в секундах остаётся отдельной настройкой.
