# Мастер подключения гарнитуры

В настройках рядом с выбором устройства звонка появился мастер: сеть → разрешение
микрофона и выбор устройств → просмотр изменений → «Настроить и подключить».
Он поддерживает локальную сеть АТС и VPN. Для прямого подключения из Интернета
требуется отдельная настройка NAT/ICE/медиатрафика; мастер не меняет роутер и фаервол.

Первичную настройку выполняет администратор/su с правом make_calls для собственного
назначенного номера. Обычные пользователи подключают уже настроенный профиль.
Мастер использует установленный FreePBX Webrtc::createDevice, а не редактирование
генерируемых конфигурационных файлов. Для номера 11 создаётся устройство 9911,
привязанное к пользователю 11. Его SIP-учётные данные отличаются от телефона 11.
При конфликте 9911 с чужим объектом создание блокируется. Совместимое уже существующее
браузерное устройство того же пользователя повторно используется без пересоздания.

Предпросмотр хранится пять минут в MariaDB softphone_setup_previews. Он привязан
к пользователю, назначенному номеру и хешу текущей конфигурации. Применение требует
явного подтверждения, повторной проверки прав, актуального назначения номера и
однократного захвата preview. FreePBX дополнительно блокирует параллельные операции
мастера над одним устройством через GET_LOCK.

После создания вызывается fwconsole reload, затем проверяются загруженные AVPF,
ICE, RTCP mux и DTLS. Только после успешной проверки профиль с зашифрованным SIP
секретом сохраняется транзакционно вместе с итогом и аудитом. Ошибка на этом шаге
вызывает попытку удаления только нового устройства с проверкой владельца и хеша.
При неизвестном результате или неудаче отката операция получает needs_review.
Старый профиль сохраняется. Повторное использование существующего устройства
никогда не разрешает его автоматическое удаление.

Требования: FreePBX Core, Webrtc, Certman с сертификатом по умолчанию, доступный AMI
FreePBX, PJSIP WebSocket, native HTTPS PBX Pulse. Сертификат сайта должен быть
доверенным на клиенте; разрешение микрофона даёт сам пользователь в браузере.
Пароли не возвращаются в preview или журнале. PHP apply выдаёт секрет только
внутреннему backend-процессу, который немедленно шифрует его для SQL-профиля.

Проверки: test:headset-setup, test:softphone-websocket-proxy,
test:softphone-auto-config, test:audio-device-access, npm run lint, npm run build.
На рабочей АТС проверяется только inspect; создание и тестовый звонок требуют
применения мастера. Миграция добавляет одну пустую таблицу, существующие бизнес-данные
не изменяет. Для отката приложения эту таблицу можно оставить.
