# HTTPS и гарнитуры

Установщик и скрипт обновления запускают HTTPS на TCP 3000. HTTP переносится на
127.0.0.1:3002 и используется только локально. Проброс TCP 3000 на роутере остаётся
прежним; в закладках, интеграциях и расширениях замените http:// на https://.
HTTP и HTTPS не обслуживаются одновременно на одном порту.

## Сертификаты

Существующая пара сертификат/ключ сохраняется. Если её нет, установщик создаёт
локальный CA и сертификат сервера в /etc/pbxpuls/tls. Закрытые ключи не публикуются.
В SAN включаются адреса интерфейсов, имя сервера и localhost. Для внешнего имени
или NAT-адреса укажите PBXPULS_TLS_NAMES (через запятую) до первой установки.
Смена имени/IP и истечение срока требуют перевыпуска сертификата администратором.
Автоматическое обновление не заменяет действующий CA и не снимает доверие клиентов.

Локальный CA необходимо один раз добавить в доверенные корневые сертификаты
компьютеров (или распространить через доменную политику). Публичный сертификат
доступен по /pbxpuls-ca.crt; перед установкой сверяйте SHA256-отпечаток с выведенным
установщиком через доверенный канал. Пропуск предупреждения браузера о сертификате
не является настройкой доверия. При наличии собственного доверенного сертификата
укажите PBXPULS_TLS_CERT и PBXPULS_TLS_KEY вместо генерации локального CA.

## Совместимость

- Штатный PBXPuls Apache-прокси pbxpuls-https.conf на 3443 сохраняется, его upstream
  переключается на локальный HTTP:3002. Перед изменением сохраняется копия,
  выполняется apache configtest, затем graceful reload Apache; Asterisk не перезапускается.
- Неизвестная конфигурация или занятый порт останавливают обновление с откатом.
- Для самостоятельно управляемого HTTPS-прокси задайте PBXPULS_HTTPS_MODE=external;
  его настройка и публичный адрес остаются ответственностью администратора.
- PBXPULS_HTTPS_MODE=off явно сохраняет HTTP без автоматической настройки TLS.
- PBXPULS_HTTPS_PORT задаёт другой HTTPS-порт. PORT задаёт внутренний HTTP-порт
  после перехода; PBXPULS_INTERNAL_HTTP_PORT задаёт его при первом переходе.
- PBXPULS_HTTP_DISABLED=true отключает внутренний HTTP, если нет Apache-прокси.
- Фаервол должен разрешать TCP 3000 для нужных сетей. 3002 наружу не открывается.
  Правила FreePBX Firewall установщик не меняет; UDP для веб-интерфейса не требуется.

Ручная подготовка: node scripts/configure-https.mjs (предпросмотр), затем после
остановки PBXPuls: node scripts/configure-https.mjs --apply. Скрипт показывает папку
резервной копии с rollback.sh. Установщик/обновление вызывают его сами.

## Аудиоустройства

Откройте https://адрес-АТС:3000 без предупреждения сертификата. В разделе гарнитуры
нажмите «Разрешить доступ к устройствам» и разрешите микрофон. До разрешения браузер
может скрывать названия и дополнительные устройства. Временный поток закрывается
сразу после перечисления устройств. Затем выберите микрофон и устройства вывода,
проверьте индикатор и тестовый звук. Кнопка выбора устройства вывода через браузер
появляется там, где поддерживается selectAudioOutput. При отсутствии setSinkId
применяется системное устройство вывода. Настройки устройств привязаны к браузеру,
компьютеру и origin: после смены HTTP на HTTPS их нужно выбрать заново.

HTTPS и доступ к микрофону не настраивают SIP-номер автоматически: для реальных
звонков также нужны профиль softphone, WebRTC/PJSIP, доступный WSS и RTP/ICE.
Диагностика и автонастройка профиля находятся в существующем разделе телефона.

При native HTTPS локальный стандартный адрес wss://тот-же-хост:8089/ws заменяется
в runtime-конфигурации на wss://тот-же-хост:3000/softphone/ws (либо настроенный
HTTPS-порт). Профиль в базе не перезаписывается. Автонастройка показывает этот же
адрес. WSS передаёт только SIP WebSocket на фиксированный ws://127.0.0.1:8088/ws;
наружу порт Asterisk открывать не нужно. Доступ требует выданный после проверки
make_calls и включённого профиля Secure/HttpOnly cookie сроком 5 минут и Origin
того же хоста. Cookie нужен для установления соединения, срок не обрывает уже
установленное соединение; после истечения и потери связи нажмите подключение ещё
раз для получения свежей runtime-конфигурации. SIP-аутентификация остаётся на АТС.
Удалённые или нестандартные WSS-адреса сохраняются. Для отключения локального
прокси предусмотрено PBXPULS_SOFTPHONE_LOCAL_PROXY=false.

Основание: https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/enumerateDevices
и https://www.w3.org/TR/audio-output/.
